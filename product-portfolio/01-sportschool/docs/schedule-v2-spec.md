# Schedule V2 Spec

Дата: 2026-05-14

Цель: заменить текущее простое расписание на модель, которая поддерживает реальные сценарии студии:
- разные дни с разным временем
- длительность занятия
- переносы и отмены
- разовые занятия
- более точные напоминания
- более честную аналитику и связь с посещаемостью

## 1. Проблемы текущей модели

Сейчас одна запись расписания хранит:
- `group_id`
- `weekdays` как строку `0,2,4`
- `time`
- `remind_before_minutes`

Этого хватает только для самого базового кейса. Не хватает:
- разного времени по дням
- длительности
- отмен и переносов
- разовых занятий
- истории конкретных занятий
- конфликта по тренеру/залу

## 2. Новая модель

### 2.1 ScheduleSlot

Повторяющееся правило.

Поля:
- `id`
- `org_id`
- `group_id`
- `trainer_id`
- `location_id` nullable
- `weekday` int `0..6`
- `start_time` string `HH:MM`
- `duration_min` int
- `valid_from` date nullable
- `valid_to` date nullable
- `remind_before_minutes` int
- `is_active` bool
- `notes` text nullable
- `created_at`

Один слот = один день недели.

Пример:
- Орлята, понедельник, 17:00, 90 минут
- Орлята, среда, 18:30, 90 минут

Это уже две разные записи.

### 2.2 LessonOccurrence

Конкретное занятие на конкретную дату.

Поля:
- `id`
- `org_id`
- `slot_id` nullable
- `group_id`
- `trainer_id`
- `location_id` nullable
- `lesson_date` date
- `start_time` string `HH:MM`
- `duration_min` int
- `status` string:
  - `scheduled`
  - `cancelled`
  - `moved`
  - `done`
- `moved_from_occurrence_id` nullable
- `cancel_reason` nullable
- `notes` nullable
- `created_at`

`Occurrence` нужен для:
- отмены отдельного занятия
- переноса отдельного занятия
- разового занятия без регулярного слота
- честного статуса “сегодня была тренировка / отменена / перенесена”

## 3. Правила работы

### 3.1 Создание расписания

Текущий мастер лучше заменить на поток:
1. выбрать группу
2. выбрать день недели
3. ввести время
4. ввести длительность
5. выбрать напоминание
6. сохранить
7. предложить `➕ Добавить ещё день`

### 3.2 Генерация occurrence

Occurrence можно создавать лениво:
- на ближайшие 14 дней
- nightly-job достраивает окно вперёд

### 3.3 Перенос

Перенос делается так:
- исходный `Occurrence` получает `status=moved`
- создаётся новый `Occurrence` на новую дату/время
- новый хранит ссылку на исходный через `moved_from_occurrence_id`

### 3.4 Отмена

Отмена отдельного занятия:
- `Occurrence.status = cancelled`
- хранится причина, если есть

### 3.5 Разовое занятие

Создаётся `Occurrence` без `slot_id`.

## 4. Как это связано с текущим ботом

### 4.1 Reminder job

Сейчас reminders читают `Schedule`.

В v2 reminders должны читать:
- только `LessonOccurrence.status = scheduled`
- только в нужную дату

### 4.2 Trainer flow

`/today` и авто-выбор группы должны смотреть не в weekdays, а в реальные occurrence на сегодня.

### 4.3 Recognition prior

Сейчас prior проверяет “есть ли у группы расписание на этот день недели”.

В v2 prior должен проверять:
- есть ли у группы `Occurrence` сегодня
- не отменён ли он

Это сделает prior честнее.

### 4.4 Attendance / finalize training

После подтверждения тренировки:
- ищем ближайший `Occurrence` для группы на сегодня
- отмечаем `status = done`

Так появится нормальная аналитика:
- запланировано
- проведено
- отменено
- перенесено

## 5. Migration plan

### 5.1 Из текущего Schedule в ScheduleSlot

Для каждой записи `Schedule`:
- если `weekdays = "0,2"` и `time = "18:00"`
- создаём два `ScheduleSlot`:
  - weekday=0, start_time=18:00
  - weekday=2, start_time=18:00

`duration_min`:
- на первом этапе default `60`
- позже можно дать админам поправить

### 5.2 Occurrence

После миграции:
- создаём occurrence на ближайшие 14 дней из новых slot

### 5.3 Совместимость

Переход лучше делать поэтапно:
1. добавить новые таблицы
2. мигрировать старые записи
3. перевести reminders на новую модель
4. перевести `/today`
5. перевести training auto-detect
6. убрать старую таблицу только после стабилизации

## 6. UI-экраны

Нужно добавить:

- `➕ Добавить слот`
- `🗓 Неделя`
- `✏️ Изменить`

### 6.2 Today
- список occurrence на сегодня
- действие `📸 Отметить`
- действие `📅 Перенести`
- действие `❌ Отменить`

### 6.3 Перенос
- выбрать новую дату
- выбрать новое время
- подтвердить
- отправить уведомление родителям

### 6.4 Отмена
- отменить сегодня
- опционально указать причину
- отправить уведомление родителям

До полной миграции можно уже подготовить:
- команды `/today`, `перенести`, `отменить`
- новый рендер списка по дням
- weekly dashboard с опорой на `training_confirmed`

1. новые таблицы `ScheduleSlot` и `LessonOccurrence`
2. миграция данных из старого `Schedule`
3. генератор occurrence
4. reminders на occurrence
5. `/today` на occurrence
6. перенос и отмена
7. привязка `done` к подтверждённой тренировке
8. очистка старой модели
