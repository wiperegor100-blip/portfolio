# VK MVP Plan

Точный план первой версии VK-направления для SportSchool Bot.

Цель:

- запустить VK не как тяжёлую копию Telegram-бота
- быстро получить пользу для роста продукта
- не ломать действующий Telegram-пилот
- использовать уже готовые сильные стороны текущей архитектуры


## Главный Выбор

Первая версия VK должна быть ориентирована не на тренера, а на:

- родителя
- руководителя как лида

Не на тренера.

Причина:

- тренерский сценарий сейчас уже работает в Telegram
- он самый сложный и самый чувствительный к ошибкам
- родительский сценарий проще переносится
- VK лучше подходит для входа, доверия, контента и коммуникации


## Первый Пользователь

Первый главный пользователь VK MVP:

- `parent`

Второй пользователь VK MVP:

- `lead / admin prospect`

Не входит в первый фокус:

- `trainer`


## Цель Первой Версии

Первая версия VK должна решать 3 задачи:

1. помогать собирать новую аудиторию
2. давать родителям полезный кабинет
3. давать студии дополнительный канал связи без отдельного приложения


## Что Входит В Первую Версию

### 1. VK сообщество продукта

Обязательно:

- название и описание продукта
- закреплённый пост с понятной пользой
- кнопка “Написать”
- короткое описание для кого продукт
- CTA для заявки / демо / подключения

Зачем:

- это точка входа для новой аудитории
- это основа для доверия


### 2. VK-бот для первого контакта

Сценарии:

- приветствие
- краткое объяснение, что умеет продукт
- выбор роли:
  - родитель
  - руководитель
- переход в нужный сценарий

Зачем:

- пользователь сразу понимает, куда он попал
- можно разветвить поток без перегрузки


### 3. Родительская привязка ребёнка

Сценарий:

- родитель получает код ребёнка
- вводит код в VK
- ребёнок привязывается к VK user id
- родитель получает доступ к кабинету

База уже есть в текущем продукте:

- child link code
- parent auth flow
- parent role

Нужно адаптировать только transport layer и хранение `vk_user_id`.


### 4. Родительский кабинет

Минимальный набор экранов:

- список детей
- карточка ребёнка
- остаток занятий
- группа
- последние посещения
- расписание
- помощь / контакты

Это уже почти полностью соответствует текущему Telegram parent flow.


### 5. VK-уведомления родителям

В первой версии нужны:

- списание занятия
- мало занятий
- reminder

Желательно:

- welcome

Почему это важно:

- это регулярная полезность
- это делает VK не просто витриной, а живым каналом продукта


### 6. Сценарий для руководителя-лида

Это не рабочий кабинет администратора, а pre-sale flow.

Минимально:

- “Что умеет продукт”
- “Оставить заявку”
- “Запросить демо”
- “Связаться”

Можно реализовать:

- через бота
- через лид-форму
- через сообщения сообщества


## Что Не Входит В Первую Версию

Сознательно не включаем:

- тренерскую отметку посещаемости по фото
- подтверждение распознавания
- ручные правки результатов распознавания
- `undo`
- полное управление учениками
- создание групп
- сложные настройки
- импорт
- финансы для администратора
- полный админский кабинет

Причина:

- это сильно увеличивает объём
- это уже работает в Telegram
- это повышает риск сорвать сроки и качество


## Что Остаётся Только В Telegram

На первом этапе только в Telegram остаются:

- рабочий интерфейс тренера
- фотографирование группы
- распознавание
- подтверждение тренировки
- списания
- отмена последней тренировки
- расширенное управление учениками
- админская операционка


## Реальные Сценарии Первого Релиза

### Родитель

1. Открывает VK-бот
2. Видит приветствие
3. Вводит код ребёнка
4. Получает доступ к списку детей
5. Открывает карточку ребёнка
6. Смотрит остаток занятий
7. Смотрит историю посещений
8. Получает уведомления о списании и напоминания


### Руководитель-лид

1. Открывает VK-бот или сообщество
2. Видит короткое описание пользы
3. Нажимает “Запросить демо” или “Оставить заявку”
4. Оставляет контакт
5. Попадает в воронку подключения

## Нужные События

Обязательные события:

- старт диалога
- выбор роли
- ввод кода ребёнка
- успешная привязка
- открытие списка детей
- открытие карточки ребёнка
- открытие посещаемости
- открытие расписания
- открытие помощи
- отправка уведомлений родителю
- нажатие “Запросить демо”
- отправка заявки

Желательно логировать:

- в каком месте пользователь вышел
- сколько родителей дошли до привязки
- сколько лидов дошли до заявки


## Что Уже Можно Переиспользовать

Почти без изменения логики:

- `core.notifications`
- `core.parent_link`
- `core.auth_access`
- `db.repository`
- event log
- parent data model

С адаптацией transport layer:

- parent welcome flow
- child link flow
- parent cabinet flow
- reminder and deduction notifications


## Что Придётся Сделать Отдельно

- VK adapter для входящих событий
- VK notifier
- маппинг `vk_user_id`
- VK session handling
- VK routing / screen logic
- VK templates for reply UI


## Риски Первой Версии

- попытка впихнуть тренерский сценарий сразу
- смешивание lead flow и parent flow без чёткого разделения
- недооценка работы по VK auth mapping
- слишком сложные меню в первом релизе
- попытка делать “полную CRM в VK”


## Критерии Успеха MVP

MVP успешен, если:

- родитель может сам привязать ребёнка
- родитель видит остаток занятий и историю
- уведомления в VK доходят стабильно
- руководитель может оставить заявку на демо
- запуск VK не ухудшает Telegram-пилот


## Рекомендуемый Порядок Работ

1. Спроектировать VK auth mapping и parent linking
2. Сделать VK notifier
3. Сделать VK parent MVP
4. Добавить lead flow для руководителя
5. Подключить аналитику по входу и заявкам
6. Только после этого решать, переносить ли trainer flow


## Итоговая Рекомендация

Первая версия VK должна быть:

- growth channel
- parent channel
- trust channel

Но не полным рабочим каналом тренера.

Это даст самый быстрый и самый безопасный путь к запуску VK без распыления продукта.
